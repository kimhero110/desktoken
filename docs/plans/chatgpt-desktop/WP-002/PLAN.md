# WP-002：桌面信号可行性验证

日期：2026-09-08；负责人：主代理。上游：WP-001 PLAN-v2，宏观目标 M-CG-DESKTOP。value-result 为本包进入 P 的证据。

## 本次执行边界

先完成只读身份与协议可达性调查，形成可复核的能力矩阵，避免用户把安装成功当成能收到完成/等待提醒。完整 WP-002 仍须满足上游真实四态、后台、关联及负例验收，本次资料调查不能替代这些测试。

允许：检查已安装包清单、签名、进程可执行文件身份；检查候选进程是否使用 stdio/具名本地传输（只输出传输类型，不输出完整命令行）；读取公开官方协议与本机已生成类型；保存不含账户、标题、聊天、凭据的调查结果。

禁止：启动模型任务、恢复用户任务、读取聊天数据库/日志/历史、连接未知认证端点、导出密钥、修改 hook 信任/应用配置、注入应用或安装监听器。本轮无 AI/RAG 处理、外部审查、运行时适配器或产品发布。

## 要求与验收

| 要求 | 本轮验收 | 不得作出的推断 |
|---|---|---|
| S-01 身份 | 包显示名、版本、可执行文件、签名及运行路径匹配有记录 | 包名能决定应用内任务模式 |
| S-02 状态语义 | 工作、等待、结束、恢复逐项记录协议字段、关联和未知项 | idle 等于某轮已完成 |
| S-03 外部连接 | 区分协议支持、当前进程传输、第三方只读订阅，未知明确标记 | 另起 app-server 能观察原桌面进程 |
| S-04 用户交付 | README 和调查报告一致说明能否进入真实提醒验证 | 文档验证通过等于桌面支持通过 |

数据仅保存应用元数据、字段名称、脱敏传输分类、来源和结论；不保存进程命令行原文、用户路径和任务内容。工作/等待用户流程必须分别有结论，不能只报文件生成数。信号字段存在仅算静态证据；真实接收、后台、时延、多任务隔离均保持未验证。

## 执行与出口

WIP=1；主代理实施及核验证据，隔离审查员检查证据边界与隐私遗漏，主代理负责最终仲裁。风险路由见 route.json。研究沿用 WP-001 两工作日估算上限；本轮最多两次实质修订，重复无证据进展则报告缺口，不制造通过。

完成矩阵后：若找到受支持且仅含状态的现有桌面订阅入口，另提交真实信号验证步骤到 R；若只是协议或非公开入口，保留“未验证”，不进入 WP-004。需要新认证、聊天内容或权限变更时回 P 重评，不能从本计划推导授权。

回滚：本次仅新增研究文档和 README 链接，可按版本恢复；不改变生产设置或运行应用。复用 prdca-governance、review-board；现有 desktop-identity-evidence 技能候选继续 defer，本次不足以证明可复用探测实现。
