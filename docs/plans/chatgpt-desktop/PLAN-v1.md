# ChatGPT 桌面工作助手：细节方案 v1

日期：2026-09-08。工作包 WP-001（方案与评审）；宏观里程碑 M-CG-DESKTOP（无需反复查看应用即可知道何时回来处理）。负责人：主代理；产品与风险接受人：用户。

## 1. 目标、证据与边界

用户明确要求集中 ChatGPT 桌面端、菜单精致便捷，并先进行 P/R 循环。本轮只写方案、评审与可逆文档，不修改应用代码、运行配置、信任或已发布版本，不发模型请求。此为重大方向调整，须返回 P/R。

已知事实：README 与 v0.4.0-beta.1 声明 ChatGPT 未接入；src/settings.html 同页展示外观、本机任务、平台凭据、自定义监视；任务接入公开六个操作和配置文本框。旧报告仅证明 OpenCode 真实链路和合成 hook 链路，不能用于 ChatGPT。

未决：用户口中的应用究竟是独立 ChatGPT Windows 客户端、Codex 应用里的 ChatGPT 对话，还是其他桌面容器。此前纠正优先，不能根据当前工具环境擅自认定目标。正式接口、本地事件、辅助功能树均未在目标版本验证。本方案中的能力全部是待验证要求，不是支持承诺。

不做：自动继续、自动授权、代用户发消息、读取聊天历史、聊天/知识库/模型市场、远程监控、其他工具扩张、会话深链接、多任务计数（未验证前）。额度功能保留。

## 3. 用户流程与界面结构

U1 首次连接：设置→连接→ChatGPT→检查连接。卡片给出实际应用名称/版本、可用能力、缺失条件；身份无法确认只显示“需确认应用”，不能显示已连接。

U2 日常工作：悬浮条显示状态；点击一次展开面板；常用“打开 ChatGPT”在面板内一个主要按钮。已有窗口优先激活，没有窗口仅在明确点击时用已验证注册入口启动；不启动 CLI 或浏览器替代。多窗口只承诺应用级打开，不承诺正确会话。

U3 等待/结束：收到可信事件→两秒去抖→系统通知；点通知打开应用。若无可靠授权事件，能力矩阵禁用授权提醒，不用普通提示框推断授权。

U4 错过提醒：面板下部最近事件，最多显示5条，可展开“查看全部”；不出现提示词/回复/聊天标题。

U5 暂停与恢复：右键→暂停提醒子菜单（15分钟/1小时/直到恢复）；右键显示恢复入口；仅暂停通知，不停止观测。重启持久化截止时间，到期恢复；直到恢复持久化。

| 层级 | 内容与数量限制 | 交互规则 |
|---|---|---|
| 悬浮条 | 保留现有额度模式；可选工作摘要，最多应用名+状态+注意标记 | 新装默认保留额度，用户选择后记忆；不在此加接入按钮 |
| 面板 | 顶部连接说明，中部当前状态/主按钮，底部最近事件 | 同时至多1主按钮+2次操作；不展示无证据任务计数 |
| 右键 | 显示模式、暂停/恢复提醒、设置、退出 | 最多4一级项；子菜单最多一层 |
| 设置 | 连接、提醒、外观三页 | 默认连接页；诊断藏在连接页折叠区；没有第四个开发者首页 |

旧配置迁移：平台凭据放“连接→额度来源”，自定义监视放其高级折叠区；CLI 配置在“连接→已有工具→高级”；外观保留现有透明度/宽度/迷你模式，开机启动归外观页底部“启动与显示”。旧设置值完整保留，不删除凭据、不重装现有 hooks。赞助/关于/更新等已有入口在U01前清点归位，不能静默删掉。

视觉基线：8px间距网格；主文13–14px、辅助文≥12px；设置建议640×520逻辑像素，面板建议320px宽、最高屏幕工作区80%，悬浮条保留用户宽度；100/125/150/200%缩放下不截关键按钮；键盘Tab/Esc可用、焦点可见；颜色辅以文字图标，正文对比度≥4.5:1。降低动态效果遵循系统偏好。状态变化和被动弹窗不得抢焦点，用户点击返回应用才允许前置窗口。若系统拒绝前置则显示“请从任务栏打开”，不得反复抢焦点。

## 4. 身份与信号验证协议

S01先取得目标 exe 路径/签名发布者、包身份（如有）、版本、窗口所属进程和用户选定窗口的一致证据，只输出上述元数据，不扫聊天标题。不能凭进程名唯一认定，不能给当前 Codex 会话贴 ChatGPT 标签。若身份仍冲突，请用户只选择一次目标窗口/应用，其他文档工作继续。

按序调查正式事件接口→本地专用状态端点→Windows辅助功能可访问状态；每条路径记录版本、可观测粒度、权限、前台/后台/最小化覆盖、语义证据和否决理由。不得注入进程、解密凭据、改授权策略、读取聊天数据库。辅助功能先限制白名单属性，禁止整树抓取文本；如果必须读正文才能识别，则停止该路径返回P。

连接状态独立于任务状态：未连接/连接中/观察可用/观察中断/不支持。配置存在不等于观察可用；观察可用需身份有效且能力自测有事件证据。

任务状态：working、needs_attention、ended、failed、unknown。只有专用语义信号才能进入ended或failed；授权与补充信息仅在接口明确区分时加reason。关闭窗口、进程退出、睡眠、断网、超时都不能产生ended。无事件但通道健康时保持状态；通道中断立即显示unknown。不能以一段沉默强行变成完成。

能力矩阵：每一行是应用身份/版本+信号源+状态+观测场景；结果为verified/unsupported/unverified。版本改变则状态重置为待验证，停止生命周期提醒，额度功能继续工作。

## 5. 技术、数据与隐私

建议保留现有 quota 模块，新增 desktop_identity、chatgpt_adapter、capability_registry；已有 task_monitor 只在后续映射设计审查后复用，不能直接把 CLI session_id 套到桌面。通知服务、应用激活器、事件记录分离。非AI确定性状态机；AI/RAG、知识库设计不适用，不在运行时调用模型。

事件 schema v1：event_id、本次进程instance_id、source_id、source_version、scope(app/window/session)、opaque_scope_id、kind、reason(enum)、observed_monotonic_ms、observed_utc_ms、source_sequence(nullable)、evidence_kind(enum)。序号若无则依适配器串行订阅；失去顺序或绑定关系即unknown，不能比较接收时间猜真实轮次。只有可证明稳定的scope才展示相应粒度。

事件正文仅上述白名单；无凭据、聊天内容、标题、窗口全文、路径中的项目名。UTC供展示，单调时钟供去抖。生命周期提醒每scope每状态转换一次，同类2秒内合并；恢复工作取消未发提醒。重启不重放旧提醒；新scope不继承旧状态。

最近事件默认仅内存、24小时/100条双上限，退出清空。导出诊断需用户主动触发，可先预览；仅能力、版本、错误码、事件类型/时间，去掉路径和scope标识。关闭连接立即取消订阅并清空该应用缓存。暂停只影响通知；断开停止观测，文案不能混淆。

权限：以当前用户运行，不提权；只观察用户选定应用；不自动批准任何请求。如正式API需要认证或新系统权限，记录最小权限，回P做风险重评，不能沿用CLI凭据。测试只用合成对话/用户显式同意的演示任务，禁止后台读取既有聊天。
