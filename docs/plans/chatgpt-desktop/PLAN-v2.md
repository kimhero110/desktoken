# ChatGPT 桌面工作助手：细节方案 v2

日期：2026-09-08。工作包 WP-001（方案与评审）；宏观里程碑 M-CG-DESKTOP（无需反复查看应用即可知道何时回来处理）。负责人：主代理；产品与风险接受人：用户。

## 1. 目标、证据与边界

用户明确要求集中 ChatGPT 桌面端、菜单精致便捷，并先进行 P/R 循环。本轮只写方案、评审与可逆文档，不修改应用代码、运行配置、信任或已发布版本，不发模型请求。此为重大方向调整，须返回 P/R。

已知事实：README 与 v0.4.0-beta.1 声明 ChatGPT 未接入；src/settings.html 同页展示外观、本机任务、平台凭据、自定义监视；任务接入公开六个操作和配置文本框。旧报告仅证明 OpenCode 真实链路和合成 hook 链路，不能用于 ChatGPT。

未决：用户口中的应用究竟是独立 ChatGPT Windows 客户端、Codex 应用里的 ChatGPT 对话，还是其他桌面容器。此前纠正优先，不能根据当前工具环境擅自认定目标。正式接口、本地事件、辅助功能树均未在目标版本验证。本方案中的能力全部是待验证要求，不是支持承诺。

不做：自动继续、自动授权、代用户发消息、读取聊天历史、聊天/知识库/模型市场、远程监控、其他工具扩张、会话深链接、多任务计数（未验证前）。额度功能保留。

## 3. 用户流程与界面结构

U1 首次连接：设置→连接→ChatGPT→检查连接。卡片给出实际应用名称/版本、可用能力、缺失条件；身份无法确认只显示“需确认应用”，不能显示已连接。

U2 日常工作：悬浮条显示状态；点击一次展开面板；常用“打开 ChatGPT”在面板内一个主要按钮。已有窗口优先激活，没有窗口仅在明确点击时用已验证注册入口启动；不启动 CLI 或浏览器替代。多窗口只承诺应用级打开，不承诺正确会话。

U3 等待/结束：收到可信事件→两秒去抖→系统通知；点通知打开应用。等待处理为不可降级核心能力；授权/补充信息仅在源事件明示时细分。目标实际存在的等待流程若不可观察，S01不通过，不能禁用后宣称完整达标。

U4 错过提醒：面板下部最近事件，最多显示5条，可展开“查看全部”；不出现提示词/回复/聊天标题。

U5 暂停与恢复：右键→暂停提醒子菜单（15分钟/1小时/直到恢复）；右键显示恢复入口；仅暂停通知，不停止观测。重启持久化截止时间，到期恢复；直到恢复持久化。

| 层级 | 内容与数量限制 | 交互规则 |
|---|---|---|
| 悬浮条 | 保留现有额度模式；可选工作摘要，最多应用名+状态+注意标记 | 新装默认保留额度，用户选择后记忆；不在此加接入按钮 |
| 面板 | 顶部连接说明，中部当前状态/主按钮，底部最近事件 | 同时至多1主按钮+2次操作；不展示无证据任务计数 |
| 右键 | 显示模式、暂停/恢复提醒、设置、退出 | 最多4一级项；子菜单最多一层 |
| 设置 | 连接、提醒、外观三页 | 默认连接页；诊断藏在连接页折叠区；没有第四个开发者首页 |

旧配置迁移：平台凭据放“连接→额度来源”，自定义监视放其高级折叠区；CLI 配置在“连接→已有工具→高级”；外观保留现有透明度/宽度/迷你模式，开机启动归外观页底部“启动与显示”。旧设置值完整保留，不删除凭据、不重装现有 hooks。赞助/关于/更新等已有入口在U01前清点归位，不能静默删掉。

视觉基线：8px间距网格；主文13–14px、辅助文≥12px；设置建议640×520逻辑像素，面板建议320px宽、最高屏幕工作区80%，悬浮条保留用户宽度；100/125/150/200%缩放下不截关键按钮；键盘Tab/Esc可用、焦点可见；颜色辅以文字图标，正文对比度≥4.5:1。降低动态效果遵循系统偏好。状态变化和被动弹窗不得抢焦点，用户点击返回应用才允许前置窗口。若系统拒绝前置则显示“请从任务栏打开”，不得反复抢焦点。

## 4. 身份与信号验证协议

S01先取得目标 exe 路径/签名发布者、包身份（如有）、版本、窗口所属进程和用户选定窗口的一致证据，只输出上述元数据，不扫聊天标题。不能凭进程名唯一认定，不能给当前 Codex 会话贴 ChatGPT 标签。若身份仍冲突，请用户只选择一次目标窗口/应用，其他文档工作继续。

按序调查正式事件接口→本地专用状态端点→Windows辅助功能可访问状态；每条路径记录版本、可观测粒度、权限、前台/后台/最小化覆盖、语义证据和否决理由。不得注入进程、解密凭据、改授权策略、读取聊天数据库。辅助功能先限制白名单属性，禁止整树抓取文本；如果必须读正文才能识别，则停止该路径返回P。

连接状态独立于任务状态：未连接/连接中/观察可用/观察中断/不支持。配置存在不等于观察可用；观察可用需身份有效且能力自测有事件证据。

任务状态：working、needs_attention、ended、failed、unknown。只有专用语义信号才能进入ended或failed；授权与补充信息仅在接口明确区分时加reason。关闭窗口、进程退出、睡眠、断网、超时都不能产生ended。无事件但通道健康时保持状态；通道中断立即显示unknown。不能以一段沉默强行变成完成。

能力矩阵：每一行是应用身份/版本+信号源+状态+观测场景；结果为verified/unsupported/unverified。版本改变则状态重置为待验证，停止生命周期提醒，额度功能继续工作。

## 5. 技术、数据与隐私

建议保留现有 quota 模块，新增 desktop_identity、chatgpt_adapter、capability_registry；已有 task_monitor 只在后续映射设计审查后复用，不能直接把 CLI session_id 套到桌面。通知服务、应用激活器、事件记录分离。非AI确定性状态机；AI/RAG、知识库设计不适用，不在运行时调用模型。

事件 schema v1：event_id、本次进程instance_id、source_id、source_version、scope(app/window/session)、opaque_scope_id、generation_id(nullable)、correlation_basis(enum)、kind、reason(enum)、observed_monotonic_ms、observed_utc_ms、source_sequence(nullable)、evidence_kind(enum)。序号若无则依适配器串行订阅；失去顺序或绑定关系即unknown，不能比较接收时间猜真实轮次。只有可证明稳定的scope才展示相应粒度。

事件正文仅上述白名单；无凭据、聊天内容、标题、窗口全文、路径中的项目名。UTC供展示，单调时钟供去抖。生命周期提醒每scope每状态转换一次，同类2秒内合并；恢复工作取消未发提醒。重启不重放旧提醒；新scope不继承旧状态。

最近事件默认仅内存、24小时/100条双上限，退出清空。导出诊断需用户主动触发，可先预览；仅能力、版本、错误码、事件类型/时间，去掉路径和scope标识。关闭连接立即取消订阅并清空该应用缓存。暂停只影响通知；断开停止观测，文案不能混淆。

权限：以当前用户运行，不提权；只观察用户选定应用；不自动批准任何请求。如正式API需要认证或新系统权限，记录最小权限，回P做风险重评，不能沿用CLI凭据。测试只用合成对话/用户显式同意的演示任务，禁止后台读取既有聊天。

## 9. R1修订：关联、可行性出口及通知证据

### 9.1 任务关联与应用聚合（CG-02/03/04/08）

稳定app/window身份不是任务关联证据。每次状态更新需满足以下之一：来源正式声明为全应用聚合状态，且通过多窗口反例；或者来源提供稳定任务/轮次身份与单调序列，证明事件属于当前generation。只按接收时间排序、只知道同一个进程或同一个窗口均不够。

若不能确定事件属于当前轮次，丢弃状态推断，显示unknown且不发结束提醒；记录无正文的correlation_lost诊断。source_sequence/generation_id字段允许空，表示源不提供该能力，不是许可猜测。适配器在S01必须交付关联证明及失败分支，证明缺失阻塞后续监控实现。

窗口A/B同时工作时，A结束不能把B写为ended；来源提供独立关联则最多展示“有任务仍在工作”，A事件仅提示“ChatGPT 有一项工作结束”，且不承诺点击返回A。没有全部活跃任务集合证据时不得说“全部完成”。全部状态面板仅在有源聚合证据或完整关联集合时展示ended，否则显示“已收到一项结束事件；整体状态未知”。没有关联能力时不支持“只通知某项结束”作为绕开S01门槛的替代。

AT-11：12组设计转实测序列，双窗口A/B交错4组、取消后同窗口新轮次/旧结束晚到4组、断连重连/复用窗口句柄4组；误聚合结束0、旧代事件改变新状态0。source构造器不能充当ground truth，至少在目标真实版本重放可操作的对应流程；无法制造或识别某类序列须标未验证并阻塞通用支持声明。

### 9.2 S01三个出口与固定分母

S01必需：身份核实、关联或正式聚合语义、工作/需要处理/结束/恢复四态、后台与最小化可观察、断连转未知、AT-01/02/03信号部分/04/11。目标真实存在的授权等待与补充信息等待都要列出：若存在却无法识别，核心需要处理能力不通过；如目标模式没有某种等待，必须用实际版本/模式证据说明“不适用”，不能因采集不到就标不存在。

出口A：上述核心全部通过，冻结应用版本、模式、信号源及覆盖范围，才可将WP-004送下一轮P/R。出口B：证据不足，WP-004保持阻塞，到2工作日预算仍无进展就停止spike并写结论。出口C：已证实不支持，停止本轮监控路线；是否仅做通知/启动器属于价值改变，交用户另作取舍，不能自批降级通过。UX信息架构可以形成方案，产品实现不越过阻塞。

AT-03固定40个真值样本：working 10、needs_attention 10、ended 10、resume-working 10。每类要求10/10正确，无排除失败或超时样本；等待样本在实际存在的授权/补充信息两类间各5，若只有一类经证据确认存在，则10个同类并在运行前冻结，禁止测完改分母。此为小规模准入门槛，不是生产可靠率证明。另以AT-04的20个负例检查错误结束0、AT-11的12组检查关联；不把负例混入状态命中率。

failed为条件能力：源无专用错误证据则显示unknown，错误提醒不可选并明确“当前版本不可识别错误”；若启用，另加10个独立错误样本全部正确。用户核心的完成/需要处理不能按此规则降级。全部测试列表在未来D前由QA冻结，编号、环境、真值、单调时间记录、预期与实际齐全；本轮所有AT仍是planned。

### 9.3 观测状态、提交结果与可见通知分开

通知状态至少区分未开启、已暂停、可提交、提交失败、可见性未确认。API成功只记submitted，不记delivered。若系统没有可靠抑制/可见回执，显示“已提交系统；是否显示受系统设置影响”；不能凭API成功点亮“通知正常”。配置连接状态不因通知被抑制而伪报断线。

AT-12：应用提醒关闭、应用暂停、系统关闭通知、勿扰抑制、API返回错误各3次。前两类不得调用系统API；后两种系统设置若不可读，记录可见性未确认；API失败有明确提示。所有样本保留内存事件和手动打开应用入口，不弹第二种抢焦点窗口，不循环重发旧事件。通知提交失败下次新事件仍可尝试，不无限重放。

时延分两段：来源真值事件发生→本机接收→API提交（含2秒去抖）p95≤5秒，前提提醒开启；单独在用户已允许通知且无抑制的环境人工记录可见时间，20个可提醒样本（等待10+结束10）应全部可见，真值→可见p95≤8秒。无法取得真实发生时间/可见证据时标未验证，不用观测时间充当源时间，不计为端到端通过。抑制场景只验收正确降级，不承诺可见。

新增Must CG-11（关联防误报）→AT-11；CG-12（通知证据分离）→AT-12。CG-03要求的信号质量与提交性能都须通过；未实现系统通知时S01只验证信号部分，不声称AT-03全通过，完整D/C仍须执行全项。

### 9.4 UX、暂停和性能补充

UI-MAP.md为本版本规范附件，含现有入口完整迁移、文字线框、动作次数与连接卡主操作；与§3冲突时按此附件更具体约束执行。新装仍默认额度，连接ChatGPT后也不自动切模式，避免菜单重构改变原用户习惯。

暂停计时：本进程用单调时钟；跨进程保存UTC截止和最后观测UTC，正常到期恢复。检测时钟回拨则继续暂停并提示手动恢复，不以负时长提前发通知；向前跳变可能触发到期，记录规则供用户理解。“直到恢复”不随重启或时间跳变恢复。睡眠恢复后先重新验证观察源，不重放睡眠前事件。

性能预算为拟定上限，以同机相同额度来源配置的关闭适配器基线相比；记录OS构建、CPU核数、应用版本、前后台、采样方法。CPU按整机总容量归一化，1秒采样；私有内存扣除基线。2小时测试是预发布准入，不是长期泄漏证明。超预算需回P评估事件订阅/轮询方案，不偷偷放宽阈值。
