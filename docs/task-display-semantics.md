# 任务列表显示语义（2026-09-08）

本页定义"本机任务"列表的诚实显示规则：只展示后端确有的数据，不推测缺失的元数据。

## 后端实际拥有的数据

接入 hook 只上报并落盘以下字段：工具名（codex / claude / opencode…）、会话 ID、项目（= 工作目录末级名称，cwd basename）、状态、时间戳。

后端**没有**的数据（因此界面绝不显示、绝不推测）：

- 任务标题 / 任务目标文本 —— 不存在任何标题来源，"项目名"只是目录名。
- 计划任务与下次调度时间 —— 无调度元数据；"本轮已停止"不代表不会再运行，后续调度状态未知。
- 输入等待的完整覆盖 —— 只有工具显式上报提问事件时才显示等待输入。

## 显示规则

| 元素 | 规则 |
|---|---|
| 工具名 | 显示人类名称：Codex、Claude Code、OpenCode、Kimi Code；未知工具首字母大写 |
| 项目 | 前缀"项目：/Project:"，明示这是目录名，不是任务标题 |
| 会话 ID | 同一工具会话间的最短唯一前缀，最短 8 位；前 8 位冲突时逐位延长直到唯一。仅当前缀在 ID 长度内无法唯一时才回退显示完整会话 ID；完整路径永不显示。判定碰撞时按行所属工具过滤同工具会话（同一会话 ID 可能出现在不同工具下） |
| 列表说明 | 不加常驻说明段落（保持面板简洁）；"项目名不等于任务标题"由"项目："前缀本身与本文档说明，停止状态的悬停/无障碍提示只解释停止语义 |
| 本轮停止 | 文案"本轮已停止 / Turn stopped"，中性灰 `#8B949E`，不用成功绿色；悬停 title 与 aria-label 均含"仅表示本轮停止，不代表任务目标完成；计划任务后续调度状态未知"，可见文案保持简短 |

## 注意力优先级

等待授权、等待输入、失败保持最强注意力色（黄/红），优先于一切停止类状态。停止只是"这轮停了"，颜色与文案都必须避免被读成"任务成功完成"。

## 已知误读与修复记录

- **目录名被当成任务标题**：旧版把 cwd 末级名称（用户实测中含字面量 `x20`）当作每行主文案，且停止状态显示成功绿——用户实测中的"多维表搭建"确为计划任务，其一轮停止被渲染成"绿色已完成"属误导。已修复：项目名带"项目："前缀、停止用中性灰与"本轮已停止"。桌面端真实任务标题在当前事件来源中不可用，界面不虚构标题。停止状态的悬停/无障碍提示只解释"本轮停止 ≠ 目标完成、后续调度未知"，不解释项目名与标题的关系——后者由本文档与"项目："前缀本身承担。
- **未实现的能力（不声称）**：任务标题查询、调度计划读取、下次运行时间推算均未实现；需另行确认可靠的本机元数据来源。
